# Changelog

Notable user-visible and operational changes, newest first.

## Unreleased

- `scripts/ui-check-k8s.sh` runs browser regression checks (`tests/ui/*.py`, headless Chromium) against the app in a temporary cluster namespace. The first one covers the review drawers: Approve & next, Prev/Next, shortcuts, unsaved-edit prompt, scroll kept after save, phone-width footer.
- `scripts/deploy.sh` builds the image on the cluster (Kaniko in a throwaway namespace, pushed to the node registry) instead of on the developer's machine; `DEPLOY_SSH` is no longer needed.
- `scripts/ci-k8s.sh` runs the quality gate (lint, tests on a throwaway pgvector database, JS check, dependency audit) in a temporary Kubernetes namespace that is always deleted, so no Docker is needed on the developer's machine.
- Keyboard shortcuts in the requirement and story review drawers: Ctrl/Cmd+Enter saves, Ctrl/Cmd+Shift+Enter approves and opens the next item, Alt+Left/Right steps to the previous/next item (shown as tooltips on the buttons).
- Fixed: on phones the review drawer's buttons ran off the right edge (613px of buttons in a 375px drawer) after Approve & next / Prev / Next were added; the footer now wraps.
- Story review works the same way as requirement review: saves, deletes, refinements update the Stories list in place (scroll, filters, ready/points tally kept), and the story drawer has **Approve & next** and **Prev / Next**.
- Reviewing requirements at volume: saving, deleting, applying an AI refinement or a bulk action now updates the list in place (scroll position, filters and the approved count stay put; before, every save jumped back to the top). The review drawer has **Approve & next** and **Prev / Next** (asking before discarding unsaved edits), and the bulk-action bar stays visible while scrolling. Measured on 300 requirements: 3 clicks plus re-finding the place per review became 1 click.
- Extraction keeps every source of a repeated requirement: when the same requirement is stated in several BRDs (or under several BRD ids), the one requirement kept lists the others (`v1.md > Capture; also addendum.docx > Changes (BR-201)`) instead of silently forgetting them.
- Story generation across many batches no longer loses stories: a story whose title matched an earlier one used to be dropped, together with its requirement links, silently uncovering those requirements. The same story twice in one feature area is now merged (links and new criteria kept); the same title in another feature area is kept, with the feature added to its title.
- Security: pypdf 6.21.0 -> 6.21.1 (CVE-2026-113786: a crafted PDF could make pypdf call arbitrary image parsers when Pillow is installed; the production image does not include Pillow, so it was not reachable here).
- Large projects: before a run, `GET /api/projects/{id}/runs/estimate` and the Extract/Generate buttons show how many AI requests it will make (exact: the same batching the run uses), a time and token estimate calibrated from this installation's finished runs, and ask for confirmation from 20 requests; a run over `Max sections per run` is refused at the click with what to change instead of failing after it started. Runs now record their request count. Additive schema change (`runs.requests`), so rolling back is safe.
- Near-duplicate detection is now exact and fast. The old shortcut (ignore words used by more than 10% of the requirements) found no duplicates at all on a repetitive BRD vocabulary, and its cost grew with the square of the project size, so creating one requirement took 4 ms at 100 items, 76 ms at 1,000 and 153 ms at 1,500 (seeding 3,000 took over 10 minutes). Prefix filtering (AllPairs) gives the exact answer: 3,000 requirements in 15 ms (was 580 ms), 6,000 in 34 ms (was 2.7 s), 12,000 in 94 ms; seeding 3,000 takes 94 s. Filter boxes on the Requirements and Stories tabs wait for typing to pause instead of re-rendering thousands of rows on every keystroke (typing a filter at 3,000 requirements lagged 2.9 s; now the table catches up 0.15 s after the last key).
- Capacity: AI calls made inside a request (Refine, Estimate, Ask the BRDs, provider test) are limited to `MAX_INTERACTIVE_AI_CALLS` (8) in flight; extra requests get an immediate 429 "AI service is busy" instead of holding a web thread. Before, 45 simultaneous Refine clicks against a hung provider froze the whole app, `/healthz` included (measured). New metric `fabulist_ai_busy_total`.
- Capacity: AI runs execute in their own bounded pool (`MAX_CONCURRENT_RUNS`, default 4) instead of the web server's shared worker threads. Before, 40 simultaneous runs made the whole app, `/healthz` included, stop answering (measured); now the 5th gets a clear 429 with `Retry-After` while everything else keeps responding. Runs with no progress for `STALE_RUN_MINUTES` do not hold a slot.
- Stuck AI runs: Cancel now stops the provider retry loop (it used to wait for every remaining retry: 31 s with a 10 s timeout, over 6 min at the default) and the run ends as *cancelled*, not *failed*; a run with no progress for `STALE_RUN_MINUTES` (15) is marked stuck when someone starts another run, so a hung provider can no longer block a project until a restart; a cancelled or stuck run can never overwrite results if its thread finishes later; the run card says when there has been no progress for 3+ minutes. Additive schema change (`runs.updated`), so rolling back is safe.
- Data portability: a full project archive (documents, requirements, stories, baselines, comments, audit history) can be downloaded from Project settings and imported from the project list as a new project, keys and links preserved. Additive; no schema change.
- AI provider errors say what to fix: a rejected key, model or access names the setting to check; running out of quota fails immediately (it is no longer retried) and keeps the provider's explanation; an unreachable provider names the host; a provider that needs a key but has none is refused when you click Extract/Generate, not after the run starts.
- First run: the Admin pages show a prominent warning when sign-in is not configured (anyone who can reach the address could change AI keys, integrations and users); Extract and Generate stay disabled with the reason shown until a BRD or requirements exist.
- Narrow screens and large text: card headers wrap instead of squeezing the title and description beside a button (the Recent changes description was 94 px wide at 320 px).
- Printing any screen (or saving it as PDF) now gives the content on white in the light palette: navigation, tabs, the workflow bar, buttons and filters are hidden, tables repeat their header and do not split rows, and nothing is clipped. Previously everything printed, and printing from a system in dark mode produced near-white text on white paper.
- Stakeholder report: shows when it was generated and its scope (approved only / everything in review; for baselines the version, name, who froze it and when), a status breakdown, A4 print layout with page numbers, repeating table headers and no split rows, and a review-and-approval block.
- Accessibility: tables that scroll sideways on narrow screens are keyboard-focusable (arrow keys scroll them) and labelled; the tab stop is removed when the table fits. Axe is clean on all 32 live pages (16 screens x desktop and phone).
- Grafana dashboard: a *Reliability and security* row (database up/down, failed sign-ins and token attempts, edit conflicts and database 503s). A test now fails if any alert rule or dashboard panel references a metric the app does not expose.
- Monitoring: `/metrics` keeps working during a database outage and reports `fabulist_database_up`; new counters for failed sign-ins/tokens, edit conflicts, database 503s and unpushed stories; new alerts `FabulistDatabaseUnavailable` (instead of a misleading "Fabulist is down") and `FabulistAuthFailureSpike`, with runbook entries.
- Confluence publishing: a page deleted in Confluence is created again on the next publish (it used to fail with 404 forever); one edit conflict (409) is retried with the fresh version; a title collision says to rename the project or the page.
- `scripts/deploy.sh` refuses to deploy from a branch other than `main`, with uncommitted or untracked changes, or when HEAD is not the latest `origin/main` (the image is built from the working tree).
- Webhooks: every delivery carries `X-Fabulist-Delivery` (stable across retries) and `X-Fabulist-Timestamp`, and with a secret `X-Fabulist-Signature-V2` signs `timestamp.body`, so receivers can reject replays and deduplicate; the body-only `X-Fabulist-Signature` is unchanged. Receiver recipe in the README.
- Git sync: the clone is pinned to the address that passed the private-network check and no longer follows HTTP redirects (a public host could previously redirect it to an internal service, or change its DNS answer between check and clone); a clone that grows past `MAX_REPO_MB` (500) is stopped; the clone timeout is `REPO_CLONE_TIMEOUT` (60 s, was 120 s, which exceeded the proxy timeout); a blocked redirect says to use the canonical URL.
- Uploads: DOCX/XLSX that would expand beyond `MAX_UNZIPPED_MB` (decompression bombs) or contain thousands of parts are refused before parsing; PDFs over `MAX_PDF_PAGES` are refused and extraction stops once enough text is read; password-protected, scanned and damaged files get a clear message; truncation (long documents, 5,000+ spreadsheet rows, 50+ sheets, long pasted text) is announced in the document text instead of silent.
- Database outages: API calls and `/healthz` return a retryable 503 (JSON message, `Retry-After`) instead of a plain 500; requests wait at most `DB_POOL_TIMEOUT` (10 s, was 30 s) for a connection; the pool validates connections when handing them out, so a database restart no longer fails the next requests (3 of 15 failed before, 0 after), and TCP keepalives detect a partitioned connection.
- Concurrent edits: requirements and stories carry a `rev`; saving from a stale editor returns 409 ("changed by someone else") instead of overwriting, and a bulk status change also makes open editors stale. Clients that send no `rev` behave as before. Additive schema change (`rev` columns with default 1), so rolling back is safe.
- Fix: the product-taxonomy cache ignored invalidation for the first 30 s after a machine boot (a new or edited product class could be missed on a freshly started node).
- Backups: the documented restore command now uses `--clean --if-exists --exit-on-error` (the old one exited 1 with 67 errors on a fresh database); `scripts/restore-drill.sh` verifies dump and restore end to end.
- Fix: going back from a project that was still loading left that project's name in the Projects breadcrumb.
- Project list: from 8 projects a filter bar (name/description, platform) and a sort (newest, name, most left to review) appear; the choice is kept while navigating.
- AI run failures name the section or story group that failed and state that nothing was saved (e.g. "Section 12 of 40 (Returns): provider returned HTTP 503. Nothing was saved; existing results were kept.").
- Tracker push: stops at a time budget (`PUSH_BUDGET_SECONDS`) and reports how many stories remain instead of timing out at the proxy; wrong credentials, permissions or URL stop the push with one actionable message instead of N identical failures; results and errors stay visible in the card and are announced to screen readers; the button says *Publish page* for Confluence.
- Baselines on phones: the table fits, with a one-line contents summary under each name and the Export/Compare actions in reach.
- Accessibility: dialog and side-panel footer buttons now meet WCAG AA contrast (4.43:1 → above 4.5:1). Links inside sentences are underlined (WCAG 1.4.1). Axe-core (WCAG 2.0/2.1 A and AA) is clean on 24 screens, keyboard-only use of the token flow verified.
- Phone layouts: Requirements, Stories (list), Sources, Product taxonomy and Activity tables keep only the essential columns so the content and row actions fit without sideways scrolling; header buttons and attribute rules wrap and stack.
- Admin: all API tokens listed on Users & roles (owner, expiry, last used) with revoke.
- Fix: the Archived view stacked under the normal project list instead of replacing it; on phones the Account and Users tables hide secondary columns so Revoke/Disable stay on screen.
- Personal API tokens (`Authorization: Bearer fab_...`) for scripts and integrations, managed on the new Account page; admin list/revoke API. Additive schema change (`api_tokens`), so rolling back is safe.
- SSO sessions end after 30 minutes of inactivity (`SESSION_IDLE_MINUTES`, `0` disables); activity slides the idle window but never extends the 8 h absolute lifetime. Existing sessions stay valid until their next request refreshes them.
- Projects are archived (read-only, restorable, audit trail kept) instead of deleted; permanent deletion is admin-only and requires an archived project. **Behavior change:** `DELETE /api/projects/{id}` now returns 409 for an active project and 403 for non-admins. Additive schema change (`projects.archived`), so rolling back to the previous image is safe.
- API requests with a body larger than the configured limit are rejected with 413 before parsing.
- Audit tab: filter the trail by action and user, page through all entries, export CSV.
- Fix: a product class added by an admin could be ignored for up to 30 s after a concurrent
  read (taxonomy cache race).
- Overview: bulk actions collapse into one row in Recent changes; clearer header label; tidier
  layout on narrow screens.
- API responses are `Cache-Control: no-store`; HSTS is sent behind HTTPS.
- `/api/meta` reports the build `version` (git revision).
- Audit trail CSV export per project.
- `scripts/ci.sh`: local quality gate (lint, tests, JS check, dependency audit, image build).
